## What this is

One typed phrase — **`gamma tango`** — that fires three skills in a fixed order so a
work session is always opened with context and always closed with the record written.

| Mode | Trigger | Order of operations |
|---|---|---|
| **OPEN** | "gamma tango", "gamma tango open", "gt open" | persistent-memory → self-improvement → git-bridge |
| **CLOSE** | "gamma tango close", "gt close", "gamma tango out" | self-improvement → persistent-memory → git-bridge |

This skill **delegates**; it does not reimplement. Each step is executed by invoking the
owning skill (`persistent-memory`, `self-improvement`, `git-bridge`) and following that
skill's own rules — including the command-bridge approval flow for anything that runs on
Jordan's PC.

## Mode selection

1. If Jordan says a mode word (open / start / begin / close / out / done / wrap), use it.
2. Otherwise infer: **OPEN** if no substantive work has happened yet in this session,
   **CLOSE** if it has (files edited, jobs run, questions answered at length).
3. State the inferred mode in one line before acting: "Gamma tango — OPEN." If the
   inference is genuinely 50/50, ask once with `AskUserQuestion` (Open / Close).

## OPEN routine

1. **Memory** — invoke `persistent-memory`. Read
   `Documents/Cowork/cowork-memory/MEMORY-INDEX.md`, load the memory file(s) whose focus
   area matches the task at hand. If the topic is not yet clear, load the index only and
   say you will load the file once the topic lands. Do not invent a topic to justify a load.
2. **Lessons** — invoke `self-improvement` and run the targeted lookup rather than
   reading the file. The log passed 73 entries and 115 KB, so "read the Pattern-Key
   lines" is no longer a cheap instruction and was measured being skipped three sessions
   running:

   ```bash
   python /mnt/user-config/skills/self-improvement/scripts/lesson_gate.py preflight \
     --surface <surface> \
     --lessons /mnt/user-config/cowork-memory/cowork-lessons.md \
     --instructions /mnt/user-config/copilot-instructions.md \
     --session <this session> --receipt-dir /mnt/workspace/.lesson-receipts
   ```

   **The receipt directory must be WRITABLE, and `/mnt/user-config/` is not** — it is the
   read-only mount of the Cowork tree. This line used to name it, which made preflight
   print every rule and then die on the receipt write
   (`lessons-gate-receipt-dir-read-only`). `/mnt/workspace/` is writable and lasts exactly
   as long as the receipt needs to.

   `preflight` prints the same rules `lesson_brief.py --for` did, and adds three things a
   lookup cannot: it FAILS if the digest in `copilot-instructions.md` is stale (so the
   rules you are reading are provably the rules in force), it FAILS if a twice-hit lesson
   on that surface has no `Rule:` line, and it writes a RECEIPT that CLOSE step 3 checks.
   Exit 1 means stop and fix, not proceed and mention it. **Exit 2 is a different animal:
   the rules loaded and every gate passed, but the receipt could not be written.** That is
   an environment fault — point `--receipt-dir` (or `COWORK_RECEIPT_DIR`) at a writable
   directory and re-run. Never report an exit 2 as a lessons failure.
   `lesson_brief.py --for <surface>` remains valid for a quick read when you are not about
   to act.

   Surfaces: `bridge`, `files`, `memory`, `skills`, `git`, `claims`. **Step 3 below drives
   the bridge, so `--for bridge` is mandatory here even when the task itself looks
   unrelated.** Open a full entry only when a rule applies and you need its mechanism.
   Name the rules applied in one short line. Silence means the lookup found nothing,
   never that it was skipped.
3. **Git baseline** — with the bridge rules from step 2 in hand, invoke `git-bridge`
   for a read-only `git status` (plus
   `git log --oneline -5`) on `C:\Users\YOURUSER\Documents\COPILOT_COWORK`, run as a `.bat`
   through the 8933 command bridge. Report the branch, the working-tree state, and the
   last commit — this is the baseline the CLOSE commit will be measured against.
4. **Report** in four short lines: memory loaded, lessons applied, git baseline, ready.

## CLOSE routine

> **Step 0 is not optional and it is new.** Until 2026-08-28 this routine had NO read
> step. Step 1 only WROTE lessons, and step 3 then drove the bridge with no bridge
> lessons loaded. That is the mechanical reason the same bridge mistake survived close
> after close: the routine that touches the riskiest surface was the one routine that
> never looked anything up.

0. **Load the rules for every surface this close will touch, BEFORE touching any of
   them.** A close always touches `bridge`, `git`, `memory` and `files`, so run all four:

   ```bash
   python /mnt/user-config/skills/self-improvement/scripts/lesson_gate.py preflight \
     --surface <surface> \
     --lessons /mnt/user-config/cowork-memory/cowork-lessons.md \
     --instructions /mnt/user-config/copilot-instructions.md \
     --session <this session> --receipt-dir /mnt/workspace/.lesson-receipts
   ```

   Sub-second per surface, and each run leaves a receipt that step 3 verifies. Name the
   rules you loaded in one line. **Do not call a bridge tool, or any git job, until
   `preflight --surface bridge` has SUCCEEDED in this turn.** Exit 1 is a stop, not a
   warning. Exit 2 is NOT a rule failure — it means the gate could not write its receipt,
   so fix the path and re-run rather than halting the close over a mount. If the script is unreachable, read the `LESSON-DIGEST` block in
   `copilot-instructions.md` instead and say that is what you used — but note that a
   fallback read leaves no receipt, so step 3 will refuse and you must say so plainly
   rather than skipping the verify.

1. **Lessons second** — invoke `self-improvement`. Capture anything from this session
   where an approach failed with a non-obvious fix, Jordan corrected a belief you acted
   on, a stored memory proved wrong, or a better method was found for something
   recurring. Write the entry with both the FAILED and the WORKED approach. If there is
   nothing worth logging, say so — an empty log is a valid outcome, a skipped scan is not.
2. **Memory third** — invoke `persistent-memory`. Update or create the focus-area memory
   file with what was decided, what changed, and what the next session needs. Lessons are
   written before memory so the memory file can reference the new Pattern-Key.
3. **Git fourth** — invoke `git-bridge`, with the bridge rules from step 0 already
   in hand. **Before the commit job runs, prove step 0 actually happened:**

   ```bash
   python /mnt/user-config/skills/self-improvement/scripts/lesson_gate.py verify \
     --surface git --instructions /mnt/user-config/copilot-instructions.md \
     --session <this session> --receipt-dir /mnt/workspace/.lesson-receipts
   ```

   `verify` exits 1 when no receipt exists for this surface and session, or when the
   digest changed after the receipt was written. That is the whole point: an instruction
   to look something up can be skipped silently, a receipt cannot be faked by intending to
   have read it. Run it for `git` and for `bridge`. Then show `git status` first, and propose the commit
   with the **exact message and file list**, wait for Jordan's approval, then write and
   run the commit job. Report the commit hash, files committed, and exit code. This repo
   is local only and is never pushed.
4. **Verify the log before calling it done.** The lessons step is not complete on
   assertion, it is complete on an exit code:

   ```bash
   python /mnt/user-config/skills/self-improvement/scripts/lesson_check.py \
     /mnt/user-config/cowork-memory/cowork-lessons.md
   ```

   Run it BARE. `lesson_check.py ... | tail` reports tail's exit status, not the
   checker's, and returned a false clean twice on 2026-08-29. Exit 0 is clean. On exit 1
   report the findings rather than describing the log as healthy.

   Then refresh the digest MECHANICALLY — never by hand-pasting the block:

   ```bash
   python /mnt/user-config/skills/self-improvement/scripts/digest_apply.py \
     --lessons /mnt/user-config/cowork-memory/cowork-lessons.md \
     --instructions /mnt/user-config/copilot-instructions.md
   ```

   It reports `already current` or `applied: N rules from M entries`, and refuses to write
   unless everything outside the markers is untouched and the block re-extracts from DISK
   afterwards. `--check` reports staleness and exits 1 without changing anything. The
   manual splice is what let the digest drift: detection was automated, the fix was not.
   A rule that never reaches that block depends on somebody opening the archive.
5. **Report** the outcomes, the rules loaded at step 0, the checker exit code, and the
   commit hash.

```
Lessons: <keys added/updated, or "nothing new to log">

```

The `Rules:` line is first in both because it is the step that used to be missing. An
empty `Rules:` line is a defect in the run, not a tidy result.

## When NOT to Use

- A plain git request ("show me the diff", "roll that back") → `git-bridge` alone.
- A plain memory request ("save memory", "what do you remember about X") →
  `persistent-memory` alone.
- A plain lesson request ("log that", "show my lessons") → `self-improvement` alone.
- Quick one-off questions that involve no work worth recording — do not bookend them.
- Anything that needs a remote/GitHub operation — this repository has no remote.

## Guardrails

- **A green gate is not a green result.** `preflight` proves the RULES were loaded and the
  digest is current. It cannot prove you applied them, and it says nothing about whether
  the job you are about to run is correct. Treat a receipt as a floor, never a finding.
- **Never touch a bridge or git tool before the surface preflight has run in that turn.**
  This applies to BOTH routines. The lookup is one sub-second call and it exists because
  the bridge lessons were repeatedly written, stored, and then not read at the moment
  they applied. Loading a bridge skill does not substitute for it: `command-bridge`,
  `local-file-bridge` and `git-bridge` all sit on top of the same traps and none of them
  performs the lookup.
- **An empty `Rules:` line means the step was skipped, not that nothing matched.** Say
  which surfaces were queried, every time. "Silence means clean" is how three sessions of
  bridge misdiagnosis went unnoticed.
- **Delegate, never duplicate.** Do not hand-roll git commands, memory files, or lesson
  entries here; invoke the owning skill so its guardrails apply.
- **The commit is approval-gated.** Never commit without showing the exact message and
  file list first. Read-only git jobs run freely.
- **The command bridge has no fallback.** If
  `jordan-approved-batch-8933-v1` / `run_batch_file` is unavailable, stop the git step and
  report the connection failure plainly. Do not write to an autorun queue, do not
  substitute artifact tools or the session `output/` folder, and still complete the memory
  and lessons steps.
- **Verify, don't trust.** Report the actual exit code and stdout of every job, and read
  back any file written.
- **Never fabricate a lesson or a memory entry** to make the routine look complete. "Nothing
  new" is a correct result.
- **No secrets** in memory files, lesson entries, or commit messages.
